📘 Academic Rationale: Binary Search Tree vs. Database Indexing

1. Role of the BST in CampusFind

In CampusFind, each report receives a unique sequential integer identifier (item_id) and a chronological date timestamp. While MySQL stores persistent records on disk, our in-memory Binary Search Tree provides:

  • Instantaneous In-Memory Lookups: Bypasses relational disk I/O and query parsing overhead for active operational lookups.
  • Natural Sorted In-Order Traversal: Yields items sorted in ascending order in $O(n)$ linear time without requiring an external sorting algorithm ($O(n \log n)$).
  • Subtree Range Pruning: Fast retrieval of records within a date or ID window ($\text{min\_key} \le k \le \text{max\_key}$) by skipping disjoint subtrees.

3. Comparative Analysis: In-Memory BST vs. MySQL B+ Tree Database Indexes

A key question in Computer Science and Engineering system design is why relational databases like MySQL use B+ Trees rather than Binary Search Trees for on-disk table indexes:

🌳 Binary Search Tree (In-Memory)

  • Binary Branching ($M = 2$): Every node has at most two children. Tree height is bounded by $\approx \log_2 n$.
  • Pointer Chasing in RAM: Pointers live in high-speed random access memory; pointer dereferencing takes nanoseconds.
  • Memory Overhead: Each node requires separate heap allocations, storing left/right pointers alongside payload.
  • Degradation Risk: If items are inserted in sorted order without self-balancing (AVL/Red-Black), height degrades to $n$, yielding linear $\mathcal{O}(n)$ performance.

🗄️ B+ Tree (MySQL / InnoDB Disk Index)

  • High Fan-Out ($M \ge 100$): Each disk page (typically 16 KB in InnoDB) stores hundreds of keys, keeping tree height extremely shallow ($3-4$ levels for millions of records).
  • Minimizing Disk I/O: Disk seeks take milliseconds. A height of 3 means at most 3 block reads to locate any record on secondary storage.
  • Linked Leaf Nodes: All data pointers reside in leaf nodes, which are sequentially chained in a doubly linked list, providing blazing fast range scans.
